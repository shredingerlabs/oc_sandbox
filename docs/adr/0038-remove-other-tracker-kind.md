# Remove the generic "other" VCS tracker kind

The tracker catalog and both creation wizards offered a fourth kind next to GitHub, public GitLab, and own GitLab: **other** — the catch-all for Gitea/Bitbucket/cgit hosts. It was functionally distinct (glab/gh never ran; tokens went to `.git_local/vcs/hosts.yml` plus the git credential-store, paste-only after ADR-0035 gave GitHub/GitLab the in-container CLI device flows) and nothing exercised it against a real host. **Decided**: tracker kinds narrow to `github`, `gitlab`, `gitlab_self`; the kind disappears from every selectable surface — Settings › VCS Tracker, the WebUI and TUI New Workspace wizards, and both workspace-settings VCS panes — and `catalogs.ValidateTracker` refuses it, so no new "other" tracker can ever be created. Non-GitHub/GitLab hosts are explicitly unsupported: creation offers `none` and users configure git themselves in-container.

**Consequences**: this is deliberately not a migration. `configure-workspace.sh vcs-credentials custom` stays as a legacy writer, and workspaces already on the `others` label stay grandfathered: their pane keeps the row (with its Host/token fields) only while it is the staged value — switching away removes it for good — and their paste-only re-login keeps working, honoring ADR-0035's promise for custom-host workspaces. Stale `kind: "other"` catalog entries (seeded by the catalogs migration) stay tolerated: Settings lists and removes them, an edit forces a valid kind, and the wizard's tracker picker plus the workspace-settings catalog prefill hide them; the migration seeding itself is untouched. ADR-0031's kind set and ADR-0035's custom-host login path are narrowed by this decision.

Decided 2026-11-17 via Grilling (Q1–Q11, shared understanding confirmed).
