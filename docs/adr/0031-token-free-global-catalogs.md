# Token-free global catalogs seed workspace VCS/provider configuration

The WebUI wish-list adds global catalogs (Settings → VCS Tracker / AI-Provider, Add/Remove/Edit) so New Workspace picks a VCS tracker and an AI provider from reusable lists instead of retyping name, endpoint, and identity per workspace. This revisits ADR-0023, which rejected a global provider registry on two grounds: tokens gathered outside workspace data, and assignment semantics reviving an "active provider". The catalogs dissolve the first ground by design — an entry is never a secret: tracker entries hold display name, git name/mail, tracker kind, and a bare host; provider entries hold display name and OpenAI-compatible endpoint; the token is typed at New Workspace and lands in the existing per-workspace flows (`.git_local/` credential bridge and gh/glab/vcs host files; `.opencode_data/credentials/<id>` with the v2 `{file:...}` reference). The second ground stays honored: the **template model** — a picked entry materializes the ordinary per-workspace configuration (`opencode.json` provider section + credential file, `configure-project.sh` vcs-credentials + gitconfig identity) and is never referenced again — keeps the provider list defined entirely by the workspace's `opencode.json`, with no active-provider record and no start-time catalog coupling. Catalogs live in `catalogs.json` in `$HOME/.config/oc-sandbox/` as a third general config file (atomic writes, backups, restore), entries unique by slugified name in insertion order, seeded one-time from existing workspaces during the rename migration.

**Considered options**: a *reference model* (workspace stores a catalog id + token; entries materialized at start) rejected — catalog renames would cascade into workspaces and start-up would couple to catalog integrity, reviving the assignment semantics ADR-0023 rejected; *catalog-only creation* rejected — an empty catalog dead-ends first-run users; *free-form creation without catalogs* rejected — the catalogs would stay incomplete and Settings → Add become a chore nobody does; *extending `global_config.json`* rejected — the three-tier split (ADR-0003) keeps preferences, workspace registry, and reusable lists apart; *inferring the tracker kind from a URL* rejected — the kind routes credentials to the gh/glab/generic host files and must stay explicit (entry field Kind, field label bare **Host** — "URL" reads as scheme+path and collides with repo URL).

**Consequences**: catalog edits never cascade; workspace edit flows keep their free-form add and gain a pick-from-catalog prefill; creation's selects offer an inline "New…" that saves the entry to the catalog before applying it, so first-run users are never forced into Settings first; "none"/no-provider stays the empty default and is never a catalog entry; a workspace may still hold several provider entries added after creation. Supersedes the global-registry rejection half of ADR-0023; its per-workspace management model stands unchanged.

Decided 2026-11-09 via [Grilling: Global VCS-tracker and AI-provider catalogs](https://github.com/shredingerlabs/oc_sandbox/issues/135).
