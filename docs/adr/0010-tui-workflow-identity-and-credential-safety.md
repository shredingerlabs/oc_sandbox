# TUI Workflow, Identity, and Credential Safety

The TUI will keep project display names unique while using a persisted collision-safe container identity derived from each canonical project root. New projects start detached for first-run setup, then attach using the selected console or OpenCode mode; deferred builds remain stopped, zero modes are valid, Podman state is authoritative, and incomplete setup exposes an explicit retry path. A failed start offers Retry, Go back, or Exit; Retry revisits edition, modes, start option, VCS, and AI settings with current values. VCS setup offers none, GitHub, public GitLab, self-hosted GitLab, and other-host choices. Every non-none VCS choice updates only project-local user.name and user.email. Credentials stay in project-local files with 700 directories and 600 files, are never logged, and are excluded from general configuration backups.
