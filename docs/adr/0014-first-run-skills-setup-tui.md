# First-Run Skills Setup as Interactive TUI Session

The skills stage of the first-run setup used `opencode run "setup-matt-pocock-skills"`, but `opencode run` is strictly non-interactive, so questions asked by the setup skill could never reach the user and the stage could not complete its job. Decided to launch the skills stage as an interactive TUI session instead: `opencode --prompt "run the skill /setup-matt-pocock-skills using the skill tool" -m "$OPENCODE_MODEL"` via `podman exec -it`, with the model coming from the `OPENCODE_MODEL` variable (`opencode/big-pickle`, a free OpenCode Zen model that requires no API key). The prompt auto-submits when the TUI is ready. Prompt wording note: upstream ships `setup-matt-pocock-skills/SKILL.md` (and other user-invoked skills) with `disable-model-invocation: true`, so OpenCode maps them to `autoinvoke: false` and omits them from the `<available_skills>` list the model sees — the earlier "run skill <name>" wording sent the model hunting for a skill that was not in its list; the current wording targets the skill tool directly (exact-name load still works). This supersedes the skills stage of ADR-0005 (headless `opencode run`); the CBM stage remains non-interactive. Trade-off accepted: a clean TUI exit (code 0) marks `setup_skills_complete` even if the user quit early — recovery is possible via the existing setup recovery flow. The default model in `opencode.json` is deliberately untouched; BigPickle is used for the setup session only.
