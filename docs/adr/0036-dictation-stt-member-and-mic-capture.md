# Dictation rides a per-workspace STT member; the host microphone comes in over a bind-mounted PulseAudio socket

Dictation (speak-into-prompt, local STT) needs a microphone the workspace container does not have, an opencode client surface that upstream v2.3 does not open to plugins (no prompt-write API anywhere; the web client runs built-in GUI parts only), and a transcription engine that must not depend on runtime model downloads. We run a whisper.cpp server as a per-workspace pod member (`oc-stt-<container-id>`, image `oc-stt`, small multilingual ggml model baked in), reach the host microphone through a bind-mounted PulseAudio socket (`PULSE_SERVER=unix:…`, socket-existence detection cascade including WSLg's `/mnt/wslg/PulseServer`), and deliver transcripts in the TUI through the plugin's review dialog (editable transcript; submitted only on the user's explicit `ctrl+enter` via the plugin client's `session.prompt`; `esc` discards; home-route dictation creates a session first), with the sanctioned OSC52 clipboard write + paste toast as the failure-only fallback, and into web sessions via a sidecar page the member serves on its published loopback port. The dictation toggle (`use_stt`) is a per-workspace boolean, preselected on at creation, applying on next container start like every other start-relevant setting (restart fingerprint, ADR 0033), and excluded under `--offline` like SearXNG (ADR 0026).

## Considered Options

- **Shared singleton STT instance for all workspaces**: rejected — breaks the pod-as-unit ops model (ADR 0029): stop/delete/restart stop working as one unit, and it needs host port allocation plus a lifecycle outside the pod; saves RAM that is bounded anyway (~≤1.5 GB with the small model).
- **speaches (faster-whisper) server**: rejected — auto-downloads models from HuggingFace at first request (egress/allowlist dependency, slow first dictation); both of our clients own the request shape, so OpenAI-API compatibility buys nothing.
- **Host-side capture daemon reached over TCP**: rejected — pasta containers cannot reach host loopback without `--map-gw`, which maps the entire host loopback into the sandbox's reach with the connection appearing as source `127.0.0.1` (trust-localhost risk, CVE-2021-20199 class); gateway-based container→host reachability was already tried and reverted on this exact stack (ADR 0028 → superseded by ADR 0029). Mic traffic stays on the unix socket, so TCP is never needed.
- **Web GUI plugin inserting via `composer.insert`**: impossible as of v2.3.0 — the web client runs built-in GUI parts only; hence the member-served sidecar page.
- **Auto-send `/dictate` command template** (in-composer web flow via `!`backtick`` shell interpolation): rejected — the transcript is submitted directly as a prompt without review, violating the review-before-send invariant.
- **Clipboard two-gesture delivery as the primary TUI route**: demoted to failure-only fallback on 2026-11-16 — the review-dialog submit route (proven working by the requester's voice-de reference plugin on opencode 2.2.5: editable dialog, explicit `ctrl+enter` submit via the plugin client's `session.prompt`, dialog retained on send failure) delivers with a single explicit confirm, keeps the review-before-send invariant (the dialog is the review), and needs no prompt-write API; clipboard + paste toast remains for delivery failures (API drift after a rebuild, send failure after retry). The auto-send template above stays rejected — it had no review step.
- **Fork/patch of opencode** (restore a prompt-append route; web-side event handling): rejected — maintenance burden against a floating upstream (ADR 0024's latest-channel install).
- **Pin the opencode version in `dist/Dockerfile`**: deferred — dictation is coupled to plugin/keybind behavior, but pinning changes the update posture for all workspaces; the risk is recorded instead (see Consequences).

## Consequences

- TUI delivery is dialog-submit (dictate key, review, `ctrl+enter`; amended 2026-11-16): upstream publishes no `tui.prompt.append` event and offers no prompt-write API (server plugins are subscribe-only; the V1 `/tui/*` routes are gone), so nothing is inserted into the composer — the plugin client's `session.prompt` submits the reviewed transcript directly. The OSC52 clipboard + paste path remains as the failure-only fallback; the probe of triggering the `prompt.paste` keybind programmatically is scoped to that fallback; not guaranteed. The `session.prompt` submit route is verified only against the voice-de prior art on opencode 2.2.5 — probe against then-current opencode at implementation.
- Web dictation is copy-paste from the dictation sidecar, not in-composer UI, until upstream loads third-party GUI parts in web tabs.
- The opencode install stays floating latest: an image rebuild can silently change plugin/keybind behavior — dictation must be re-verified against the then-current opencode after rebuilds; if breakage recurs, revisit the pin.
- The TUI plugin part runs unsandboxed inside the TUI process (child processes, fs, HTTP — and, since 2026-11-16, prompt submission via the plugin client) — the same trust class as upstream's `!` shell, which runs outside the permission flow.
- ~≤1.5 GB RAM per running STT-enabled workspace and a ~1–1.5 GB larger `oc-stt` image (small ggml model baked in).
- Capture health is per-boot (WSLg's RDP transport has open stream-creation bugs): the first transcription attempt doubles as the health check; failure toasts "no audio input" while the sidecar keeps working. Hosts without an audio socket skip the mount entirely — the member still starts so the sidecar works.
- On SELinux distros the socket mount wants `label=disable` (Ubuntu 24.04/AppArmor is unaffected).
- The member carries the first pod member with a host port publish; loopback-only, following the web (4096)/CBM (9749) precedent.
- `ctrl+t` is claimed by our plugin via the keymap layer; no stock keybind is overridden and the seeded cli.json stays untouched.
- `!` shell commands (and our TUI plugin) execute outside the agent tool permission flow — an upstream property, noted here because dictation adds an in-container component users may not think of as privileged.

## Amended 2026-11-16 (implementation)

Build-time decisions made while implementing #165–#170 (decisions.md in the #164 working notes), plus fact corrections to the pre-implementation wording above:

- **Keybind — `ctrl+t` is not default-free**: the stock `variant.cycle` keybind defaults to `ctrl+t` (verified against the opencode v2.2.6 binary), so the spec's "chosen from default-free keys — no stock keybind overridden" was factually wrong. Decision (the requester's voice-de pattern): dictation claims `ctrl+t`; the stock `variant.cycle` **chord is freed via the seeded `cli.json`** (`"variant.cycle": "none"`, merged, never clobbering user values — start.sh seeding). `variant.cycle` stays reachable from the command palette; no other stock keybind is touched. The "seeded cli.json untouched" consequence line above is superseded by this amendment.
- **Port constant: 8090** (not the whisper.cpp 8080 default, which would collide with searxng's in-pod `127.0.0.1:8080`) — verified against whisper.cpp's server: `--port`, `--host` (the server default is loopback, so `--host 0.0.0.0` is required for the pod publish), `--public PATH` static serving, `--inference-path` default `/inference`. Request shape verified against the pinned server README: `POST /inference` multipart (`file=@audio.wav`, `response_format=json`) → `{"text": "..."}`. The `--public` static mount serves the dictation sidecar from the same port — no front server, one process per member.
- **whisper.cpp pinned v1.9.5** (build-time `git clone --branch`); small multilingual model `ggml-small` (~466 MB) baked at build with sha256 verification — zero runtime downloads.
- **Offline + dictation is a silent skip, not a hard exclusion**: `--use_stt --offline` starts normally without the member (a note is logged); unlike searxng/CBM there is no validation error. The earlier "excluded under `--offline` like SearXNG (ADR 0026)" wording reads too strictly.
- **The TUI has no display-mode matrix**: the Standard/Advanced presentation matrix exists only in the WebUI (Go TUI has no display-mode mechanism), so the TUI wizard/settings show the dictation row unconditionally — "advanced-only like the other option rows" holds there by virtue of there being no hidden TUI rows (D8).
- **Recording cap: 300 s constant** (`RECORDING_CAP_MS`), not a settings key (D4). Sidecar silence-trimming: none in v1 (D5).
