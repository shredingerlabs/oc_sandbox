# Context

## Glossary

**workspace** — The unit oc-sandbox manages for a user: a registered folder (the workspace root) holding its content, configuration, and container fleet; the central domain noun of this project. _Avoid_: project (the pre-rename noun; survives only until the one-time migration and in the archival record), project folder, project root (say workspace root), app, instance, sandbox (oc-sandbox is the whole tool, not one workspace), container (a workspace is not its container), repo (a repo is a git source/folder inside a workspace — a single repo sits at the `workspace/` content-dir root today, and the future multi-repo workspace puts further repos in `workspace/` subfolders; not every workspace contains code or a repo).

**MCP server config** — OpenCode (v2, ADR 0025) uses `mcp.servers.<name>` with `type: "local"` and `command` as an array. The v1 flat `mcp` map is migrated at workspace start; legacy `enabled: true` is dropped (`disabled: false` is default). Claude Desktop's `mcpServers`/`command`-string/`args` schema is incompatible.

**CBM (codebase-memory-mcp)** — Knowledge-graph indexing tool. Uses `auto_index` and `auto_watch` config (persisted to `.cbm_cache/`) instead of manual entrypoint hooks. UI variant is always installed; `--cbm_ui` flag toggles runtime behavior only.

**TUI (Text-based User Interface)** — Primary user interaction method: the single Go binary `oc-sandbox` (BubbleTea), providing structured navigation, validation, and workspace management while maintaining terminal compatibility. The former gum/bash TUI (`start-tui.sh`) was deleted after the parity-gate flip (#98, cleanup #99).

**sandbox_config.json** — Per-workspace configuration file stored in `<workspace_root>/.opencode_config/` containing container edition, modes, auto-start options, CBM settings, and setup completion status.

**workspace source** — Where a new workspace's code comes from: "Blank Workspace" (wizard-created scaffolding) or "From Repo" (clone existing repo via URL, in-container clone during first-run setup; the data values stay `empty`/`cloned`). Avoid: project source (the pre-rename term), import repo, repo migration, connect repo.

**workspace kind** — What a workspace is for, chosen by the New Workspace wizard's Agent row (identical for both workspace sources): `code` (default, standard agent rules), `chat` — the "Chat Agent (NO_CODE)" option for a non-code workspace that behaves like plain AI chat — or `pkm` — the "PKM (Personal Knowledge Wiki)" option, which additionally pins the edition and seeds the PKM templates (see pkm edition, ADR 0027). Decided and recorded once at creation (`workspace_kind` in sandbox_config.json, absent reads as code); never re-applied or offered in the revisit sequence — later changes are a hand edit of `.opencode_config/AGENTS.md`. Avoid: project kind (the pre-rename term), nocode workspace, agent template, NO_CODE workspace.

**pkm edition** — Container edition for Personal Knowledge Wiki work (`opencode-sandbox-pkm` stage in dist/Dockerfile, building from base like every shipped edition): no additional installs, only the `ENTRYPOINT ["/bin/bash", "-l"]` that base lacks. Handled like every other edition everywhere (runtime detection, Build Images / Delete Images, build plan, start, edition mismatch); selectable by the TUI only implicitly — when a new workspace's workspace kind is `pkm`, the Edition row is hidden and `container_edition: "pkm"` is forced at creation. Edition switches later (revisit sequence, next-start apply) remain allowed in both directions, but the PKM seeding — `AGENTS.md` (the wiki schema, overriding the code/chat swap), `agents/`/`commands/`/`skills/` templates, `default_agent` + `permissions` appended into opencode.json, pkm `.gitignore` entries appended with dedupe, and the `notes/`/`raw/`/`wiki/` vault skeleton in `workspace/` — happens only at creation; switching to pkm later yields the image, never a re-seed. Templates also seed over anything an in-container clone brought (same as chat). Avoid: PKM workspace type (it is a workspace kind, not a separate type axis), wiki edition.

**repo URL** — The git remote URL recorded at workspace creation for a `cloned` workspace; stored in sandbox_config.json and the workspace registry, and used to derive git tracking and re-check repo reachability. _Avoid_: repo link, clone URL (ambiguous with the act of cloning).

**in-container clone** — Cloning the repo URL inside the workspace container during first-run setup, after container start and before CBM configuration, using the container-side VCS credentials; chosen so host machines need no git/SSH setup. _Avoid_: host clone, URL import.

**workspace import** — TUI flow (Settings → Import workspace) that registers an existing folder as a workspace *only when it is a sandbox workspace root* (valid `sandbox_config.json` plus a `workspace/` git worktree; missing infra directories like `.cbm_cache` are no obstacle — start.sh re-creates them at every container start); a summary screen confirms it and only the registry changes. Non-matching, legacy-layout (`project/`, pre-migration roots — see the migration plan), or broken-config folders are never migrated/copied — the flow shows an informational prompt and offers a jump into the New Workspace wizard, where code comes in via the ordinary new-workspace sources. An already-registered path hits the registered guard regardless of its folder's state. There is no "import" workspace source; `workspace/` content of a matching root is left untouched. _Avoid_: project import (the pre-rename term), folder migration, import repo.

**git init heal** — Host-side `git init` performed at container start when `workspace/` has no `.git`, guaranteeing OpenCode-Web always finds a worktree; skipped for workspaces whose workspace source is `cloned`.

**workspaces.json** — Global workspace registry stored in `$HOME/.config/oc-sandbox/` with workspace metadata including names, paths, container states, and last-used timestamps for ordering. Pre-rename name `projects.json` (top key `projects`) is migrated one-time. _Avoid_: projects.json (the pre-rename filename), project registry.

**global_config.json** — Global user preferences stored in `$HOME/.config/oc-sandbox/` containing `default_workspace_path` and user-specific settings not tied to individual workspaces.

**catalog** — The global pair of reusable-settings lists managed in Settings → VCS Tracker / AI-Provider: the **tracker catalog** and the **provider catalog**. Catalog entries are reusable starting points picked at workspace creation, never workspace-specific state; a token is typed per workspace at creation and a catalog entry never holds a secret. Stored in `catalogs.json` in `$HOME/.config/oc-sandbox/` (third general config file: atomic writes, backups, restore), seeded one-time from existing workspaces during the rename migration. The creation form's selects also offer an inline "New…" that captures the entry into the catalog before applying it. _Avoid_: registry (workspaces.json's noun, and the per-entry global registry ADR-0023 rejected), preset (the removed GWDG flow), template (implementation metaphor).

**catalog entry** — One reusable row of a catalog: a **tracker entry** (display name, git name/mail, tracker kind — GitHub / public GitLab / own GitLab / others — and a bare host, required for own GitLab/others) or a **provider entry** (display name, OpenAI-compatible endpoint). Picking one at creation materializes today's per-workspace configuration unchanged (provider section + credential file; VCS credentials + gitconfig identity) and the entry is never referenced again: editing a catalog entry does not cascade to workspaces created from it. Catalogs are the source at creation; workspace edit flows keep their free-form add (with a pick-from-catalog prefill), and a workspace may still hold several provider entries. "No tracker" / "no provider" is the empty default, never a catalog entry. _Avoid_: catalog item, template entry.

**concurrent containers** — Multiple workspace containers can run simultaneously using workspace-specific naming (opencode-sandbox-WORKSPACENAME), with TUI using podman exec for accessing running containers instead of starting new ones.

**stop container** — Graceful shutdown of a running workspace container — via `podman pod stop` on the workspace's pod (`opencode-sandbox-pod-<container-id>`; running containers inside it, companions and all, go down as one unit, #125) or via plain `podman stop` (SIGTERM, then SIGKILL after the default timeout) when no pod exists (pre-upgrade runs), initiated from the TUI Settings menu for a single selected workspace. Because containers run with `--rm`, a stopped container is removed automatically; the registry's container_status (keyed to the workspace container name) is set to "stopped" only after the container is verified gone.

**start container (Container center)** — Starting a registered workspace's container from the Container center's Start tab (distinct from the Open Workspace flow): start.sh runs with the values stored in sandbox_config.json (edition, modes, start_option, proxy, `--detach`; identical arg rebuild to the Open Workspace start). Already-running containers are reused, not restarted. The registry's container_status is set to "running" only after every started container is verified live via `podman ps`. _Avoid_: silent restart (the reuse is explicit).

**restart** — Explicit, confirmed WebUI replacement of a RUNNING workspace container (ADR-0033; deliberately overturns the earlier never-killed rule): the card's Restart stops the running container and starts a fresh one with the saved settings, registry flipping truthful like every op (stopped after the verified stop, running after the verified fresh start). Active only for a running container whose **started-config evidence** is stale: the fingerprint over the start-relevant sandbox_config.json fields (edition + modes + proxy + search mode), the workspace image's ID, or both drifted since the last start — or the evidence is absent (pre-feature runs). Edition mismatches preflight the saved edition's image before anything stops; the edition-mismatch switch stays the edition-specific path. Distinct from a Server restart (oc-sandbox the process, never itself restartable in-WebUI). _Avoid_: server restart, reload, reattach (session re-entry without any container change).

**delete container** — Removing an existing oc-sandbox container from the Container center's Delete tab; the checklist lists every sandbox pod (`podman pod ps` filtered by the `opencode-sandbox-pod-` naming convention; the pod row also carries its workspace container, so members are never listed separately) alongside every pod-less legacy container in any state (`podman ps -a` filtered by the `opencode-sandbox-` convention), including exited/created leftovers of gone workspaces, with the workspace name echoed for registered ones. Running units are refused with a stop-first hint (`podman pod stop <pod>` for pods, `podman stop <name>` for containers) — deleting a running unit would be an ungraceful kill, and pods are never force-killed. Removal runs `podman pod rm` (pod-as-unit, no force needed after stop) or `podman rm` (no force needed for non-running), verifies gone against a fresh `podman pod ps` / `podman ps -a` before any registry touch, and then only flips a stale container_status (keyed to the workspace container name, `running` → `stopped`). container until it is replaced). Delete always works on non-running units in any state (stopped/created/missing); the live one's delete button greys with the reason instead of vanishing, and the server keeps its fresh-state refusal regardless. It frees the unit's writable layer only (real data lives in host bind-mounts; images are untouched). _Avoid_: force delete, image delete (rmi), delete workspace.

**build plan (New Workspace)** — Recorded Build now / Build later radio choice of the New Workspace form: while the selected edition's image is missing, an inline "Image build" row sits directly under the Editions row (image-existence memoized per edition for row visibility; create re-checks fresh). The create confirm popup lists it ("image build: …") and the Create button executes it: Build now runs build-container.sh, revalidates the image, then proceeds; Build later registers the workspace stopped (deferred build). While the create chain runs (build, init, credentials), the New Workspace view streams every step into an embedded log pane below the form card — the form stays visible but inert until the chain ends; the pane stays readable after a failure. Replaces the former create-time Build now / Build later / Go back prompt (Go back dropped — the form itself is home); the start-time prompt keeps its Go back. _Avoid_: build prompt (start-time prompt unchanged), build wizard.

**first-run setup** — Automated container initialization including in-container probe (`git ls-remote`) and full clone for cloned workspaces, then CBM configuration and skills setup, tracked via `setup_clone_complete`, `setup_cbm_complete`, and `setup_skills_complete` flags in sandbox_config.json, offering granular recovery for partial failures including Retry / Change URL / Exit for clone issues.

**host terminal window** — A terminal window oc-sandbox opens on the host to host an interactive session that must live in a real terminal: the console/OpenCode start variants launched from the WebUI, and the first-run setup's skills stage, whose window opens automatically when the stage arrives. When no window can be opened (headless machine, SSH), the WebUI shows the exact copyable command instead and the session stays pending until it completes in the user's own terminal or is cancelled. _Avoid_: terminal handoff (the BubbleTea TUI's suspension mechanic — never a WebUI feature), in-browser terminal, popup.

**VCS integration** — Version Control System setup (GitHub, GitLab, or custom host) creating host token files (`gh-cli/hosts.yml`, `glab-cli/config.yml` with a `hosts:` block — glab ignores a separate `hosts.yml`, or `vcs/hosts.yml`) in `.git_local/` subdirectories, separate from AI provider configuration.

**AI provider** — The OpenCode model backend available to a workspace, managed as provider entries inside the workspace's own config files; which provider's models are used is chosen inside OpenCode at runtime, not by the TUI. A configured provider is an `@opencode/ai/providers/openai-compatible` section in `opencode.json` (v2 `providers.<id>`, ADR 0025) with its credential in the per-provider token file under `.opencode_data/credentials/`. The sandbox_config.json `ai_provider` field is legacy: creation still records it, but the workspace edit flows neither read nor write it. _Avoid_: GWDG preset (removed; `gwdg-saia` survives as a legacy entry that coexists with others; entries lacking a credential render read-only with an orphan hint), vendor preset, assigned provider.

**custom provider** — Name / Endpoint / Token captured as one block (wizard at creation, Edit Workspace settings screen for edits). Name is display name and id source; Endpoint is the OpenAI-compatible baseURL; Token is the API key. A workspace may hold several at the same time. Stored without any vendor preset. _Avoid_: GWDG flow, preset provider.

**provider entry** — One configured provider inside a workspace: the `providers.<id>` section in opencode.json (v2; the legacy `provider.<id>` shape is read for pre-migration display only, ADR 0025) plus its matching credential file. The smallest manageable unit of AI provider configuration; add, edit and remove act on entries, never across workspaces. _Avoid_: provider record (ambiguous with the legacy sandbox_config entry), active provider.

**provider list** — The set of provider entries of the currently selected workspace, shown by the Edit Workspace settings screen; defined entirely by opencode.json. Not a global or cross-workspace registry. _Avoid_: global provider list, provider registry.

**provider id** — Slugified key derived from the typed provider name (lowercase, non-alphanumeric runs → `-`, trimmed) used as the credential-file name under `.opencode_data/credentials/` and the `providers.<id>` section key in `opencode.json`. Renaming an entry moves its id (the old section is replaced by the slugified new one). Legacy sandbox_config values may reference `gwdg-saia`. _Avoid_: provider name (the display name is separate), auth key.

**provider endpoint** — The OpenAI-compatible API base URL (scheme `http://`/`https://`, no whitespace, path allowed) offered by a custom provider, mapped to OpenCode `settings.baseURL` (v2). _Avoid_: provider URL (ambiguity with the recorded provider id), host (no scheme/path implied).

**v2 config migration** — One-time in-place rewrite of a workspace's v1-shaped `opencode.json` (flat `mcp`, `permission` map, `plugin`/`provider` keys) to the OpenCode v2 schema, plus extraction of legacy `auth.json` tokens into per-provider credential files (the old file is renamed `auth.json.v1-migrated`, never deleted). Idempotent; runs before every container start and lazily before each provider subcommand, so a routine image rebuild restores providers instead of silently dropping them. _Avoid_: config upgrade (reads as general TUI updates), re-import.

**credential file** — Workspace-local VCS or AI secret configuration stored separately from global TUI metadata, with restrictive permissions and excluded from general configuration backups. AI provider tokens live one file per provider id under `.opencode_data/credentials/` and are referenced from `opencode.json` via the v2 `{file:...}` substitution (ADR 0025), not in `auth.json`.

**install script** — Script that downloads and sets up the opencode-sandbox files to a designated installation directory.

**installation folder** — Directory where opencode-sandbox files are stored, defaulting to `$HOME/.oc-sandbox` but configurable via `--install_path`.

**bash one-liner** — Single bash command that downloads and executes the install script from GitHub.

**latest release** — The most recent tagged release on GitHub, used as the default version for installation.

**update mode** — Installation behavior when the installation folder already exists; interactively prompts [y/N] to confirm the update, or runs non-interactively when the caller pre-confirms (TUI-invoked updates).

**version flag** — Optional `--version` parameter to install a specific release tag instead of latest.

**VERSION file** — Install-folder marker holding the installed release tag, rewritten by the install script on every install and update; the version shown in the update menu comes from it, falling back to the binary's compiled version when absent. _Avoid_: version number, release tag (the tag value itself).

**update check** — TUI-side background query of the latest GitHub release, run at every startup and compared against the installed version; failure (offline, rate limit) is silent and leaves no badge, and the result is never persisted between runs. _Avoid_: auto-update (nothing is installed automatically), update detection.

**update menu** — Settings sub-tab directly left of Uninstall, showing installed and available oc-sandbox versions with the Update action behind the confirmation popup (ADR-0021); while an update is available, a footer badge appears that jumps here on click, and after an update the menu notes that restarting oc-sandbox applies it. _Avoid_: update tab, upgrade menu.

**update phase** — The state of the self-update surface, one of `up-to-date`, `available`, `installing`, `applied`, `failed`: the footer banner and the update card render from it. `available` carries the badge; `installing` means the update op is running (the task queue accepts nothing else until it ends); `applied` is installed-but-not-running — the banner clears, and the persistent "Update installed — restart oc-sandbox to apply" note stays on the update card, with a completion toast; `failed` keeps the error visible until the next attempt. _Avoid_: update state, badge status.

**server-stopped screen** — The browser screen an open WebUI tab ends on when the WebUI server is gone: pushed best-effort via SSE on quit, and rendered by the client itself when reconnect attempts exhaust (hard crash, no push possible). It reads "server stopped — relaunch oc-sandbox" and never auto-redirects or reconnects — the per-launch token dies with the process, and the relaunched instance opens its own fresh tab. One screen for both causes. _Avoid_: dead tab, stale tab, reconnect prompt.

**display mode** — The WebUI's Standard/Advanced presentation switch: a segmented control in the header of every screen, persisted as `display_mode` (`standard` / `advanced`, default `standard`) in global_config.json, applied immediately by reactive re-render with no reload. Standard preselects at creation and hides preset rows everywhere; Advanced always reveals the stored values — presets, not pinning: the stored sandbox_config.json is the single truth, and Advanced edits of Standard-hidden options are sticky. _Avoid_: theme (dark/bright colors are a separate toggle), fixed mode (nothing is fixed; rows are preset and hidden).

**github API fallback** — Uses GitHub releases API to detect latest release; falls back to HTML scraping if API fails.

**git clone method** — Uses `git clone --depth 1 --branch <tag>` for clean repository handling.

**fallback method** — If git is not available, downloads release tarball from GitHub as alternative.

**cleanup** — Removes `.git` directory after installation to save space and prevent accidental git operations.

**executable permissions** — Automatically sets executable permissions on all `.sh` files during installation.

**update prompt** — When installation folder exists, prompts user with [y/N] (default no) to confirm update.

**temporary directory** — Uses system temp directory (`/tmp` or `$TMPDIR`) for downloads and extraction; cleans up after installation.

**verbose output** — `--verbose` flag enables detailed logging; default is minimal progress information.

**permissions** — Never uses sudo automatically; fails with clear error messages on permission issues.

**network retry** — Retries network operations automatically 3 times with exponential backoff before failing.

**disk space check** — Validates minimum 500MB available disk space before starting installation.

**convenience artifacts** — The two launcher-bits the install script creates by default so the TUI is reachable everywhere: the entry-point symlink and the desktop shortcut. Both are opt-out, never fail the installation, and can be deselected individually via `--no_symlinks` / `--no_shortcut`. _Avoid_: convenience features, extra flags.

**symlinks** — The symlink artifact of the convenience artifacts: a single symlink `oc-sandbox` → `bin/oc-sandbox` (the Go TUI binary) in `$HOME/.local/bin` for easier command access. Created by default; deselected with `--no_symlinks` (the former opt-in `--symlinks` flag is accepted as a no-op). Desktop shortcut points at the binary too. Default entry point since the parity-gate flip (#98); the former `--bash-tui` escape hatch went away with the bash TUI deletion (#99, ADR-0020).

**color output** — Install script output uses plain text only for maximum compatibility. Helper scripts may use gum for prompts (e.g. the uninstall wizard's red confirmation input), with plain-text fallback; the Go TUI renders via Lip Gloss.

**exit codes** — Standard exit codes: 0 (success), 1 (general error), 2 (user abort), 3 (missing dependencies).

**configuration preservation** — During updates, asks before overwriting `proxy/allowlist.txt` with option to skip; overwrites all other files.

**shell compatibility** — Written for bash specifically (`#!/usr/bin/env bash`) for cleaner syntax and better feature support.

**dependency checking** — Checks for required tools: curl or wget, tar, grep, awk, sed; fails with clear error if any missing.

**user prompts** — Uses basic `read -p` prompts with explicit Enter key instructions.

**help documentation** — Supports `--help` flag showing usage, available flags, and examples.

**curl fallback** — Bash one-liner prefers `curl` but falls back to `wget` if curl is not available.

**script execution** — Bash one-liner uses pipe directly (`curl ... | bash`) for simplicity; security implications documented.

**installation validation** — Validates key files exist and are executable after installation; reports issues if found.

**progress indicators** — Uses simple status messages during operations; no progress bars or spinners.

**signal handling** — Handles SIGINT (Ctrl+C) gracefully to clean up temporary files before exiting.

**symlink creation** — Creates a single entry-point symlink `oc-sandbox` → `bin/oc-sandbox` (Go TUI binary, default since the parity-gate flip #98) unless deselected with `--no_symlinks`; removes stale symlinks in `$HOME/.local/bin` pointing into the install path first (ADR-0020). Fail-soft: a failing symlink (e.g. unwritable `$HOME/.local/bin`) warns with a manual `ln -s` hint and continues the installation.

**symlink overwriting** — Overwrites existing symlinks without prompting (default behavior; deselect with `--no_symlinks`).

**temporary file naming** — Uses random names with `mktemp` for temporary files to avoid conflicts.

**error message paths** — Uses absolute paths for all error messages to avoid confusion.

**logging** — Only outputs to stdout/stderr; no log files created during installation.

**github API authentication** — Stays unauthenticated for simplicity; handles rate limit failures gracefully with fallback to HTML scraping.

**user agent** — Sets a simple user agent identifying the opencode-sandbox install script for GitHub API requests.

**version comparison** — The update check's comparison of the installed release tag against the latest GitHub release; non-comparable or unknown tags count as outdated (update offered). The interactive install script itself still prompts regardless of versions.

**special file handling** — Only `proxy/allowlist.txt` gets special treatment during updates; all other files are overwritten.

**post-installation message** — Shows brief reminder about system requirements (podman, etc.) and suggests next steps after successful installation.

**setup-complete marker** — Boolean flag in sandbox_config.json tracking whether first-run setup (CBM configuration and skills setup) has been completed for a workspace.

**atomic config write** — Configuration update method using temporary files and atomic rename operations to prevent corruption during crashes, with automatic backup creation.

**runtime detection** — Dynamic discovery of available container editions and modes at runtime, avoiding hardcoded lists. Editions come from the Dockerfile stage registry (ADR 0019): every `FROM ... AS opencode-sandbox-<name>` stage in `dist/Dockerfile` or `dist/Dockerfile.custom`, grepped live at each menu render. Modes are still parsed from start.sh help text. _Avoid_: hardcoded edition lists, help-text edition parsing.

**base edition** — The parent stage `opencode-sandbox-base` in `dist/Dockerfile` that all shipped editions build `FROM`: infrastructure, not a user-facing edition. The Go TUI never offers it as a selectable edition for a workspace (New Workspace wizard, change-settings, re-selection); it remains discoverable and buildable via the Container center Build Images tab, `build-container.sh`, and `start.sh`. Workspaces stored with `container_edition: "base"` stay valid. _Avoid_: base image edition, selectable base.

**latex edition** — Container edition for LaTeX/TeX document work (`opencode-sandbox-latex` stage in dist/Dockerfile, building from base like every shipped edition). Full compile toolchain: latexmk plus the texlive collections recommended/extra/science/bibtex-extra/publishers/xetex/luatex/pictures/plain-generic/extra-utils/lang-european, biber, chktex, latexdiff, ghostscript, poppler-utils, dvipng, python3-pygments (minted), tex-gyre, lmodern, pandoc, Liberation/Noto fonts, and matplotlib/pandas (apt) for plot generation. Deliberately fat: any document should compile first try, no rebuild-on-complaint. Stands alone from the writing edition — duplicates pandoc and the font packages rather than layering (writing keeps its own pandoc for office/docx conversion), keeping edition images independently rebuildable. Provision-only: tools are shell-invocable, nothing is seeded into opencode.json. _Avoid_: TeX edition, writing edition (the LibreOffice sibling).

**image-existence marker (Build Images)** — Status shown on each edition row of the Container center Build Images tab: `● built` when the edition's image exists in podman, `○ missing` otherwise. Checked once per tab entry and re-checked when a build finishes (a check that fails reads as missing); rows render without any marker before the first check. _Avoid_: live per-render check, missing image (the start-time error about a missing image is a separate concern).

**build images (Container center)** — Container center Build Images tab: lists the live edition registry (ADR 0019, base included) with the image-existence marker, plus select-all and a Build button; building checked editions runs build-container.sh as one sequential op through the task manager, streamed into the embedded log pane. Creates images, never containers. _Avoid_: build container (misnomer — podman builds images), build prompt (the start-time Build now / Build later prompt is a separate flow).

**delete image** — Container center Delete Images tab (directly after Build Images): lists every sandbox-family image as a checklist row with tag, size, and use marker — `● in use` when the image is in use, `○ unused` otherwise. In use means: any container in any state references the image — edition images by their edition suffix (the container's ref carries no registry prefix or tag), infra images (oc-proxy, oc-searxng) by name — or, for the sandbox family's dependent images (the infra images and parent stages such as base), any container in any state references **any edition image at all**: the sandbox family loses the pin together, with the last edition container. A direct infra container ref itself keeps its pin. Unrelated host images and dangling `<none>` images are never listed, and there is no prune action. In-use images are refused with a remove-containers-first hint (podman rmi never deletes a referenced image); removal runs `podman rmi` per checked image behind the danger confirmation popup, verified gone against a fresh image list. Deletion also refreshes the Build Images tab's existence markers. _Avoid_: image delete (ambiguous with delete container), image prune (no prune action).

**custom edition Dockerfile** — User-editable `dist/Dockerfile.custom` holding user-defined edition stages as standalone build recipes (typically `FROM opencode-sandbox-base`, ending `USER dev` + `ENTRYPOINT ["/bin/bash","-l"]`). Shipped as a commented example template on install; never overwritten on update — recreated only if absent. The main `dist/Dockerfile` is still overwritten on update, so it is not a sanctioned home for user stages. _Avoid_: edition manifest, editions.json.

**native script enhancement** — Strategy of extending existing scripts (start.sh, build-container.sh, init-workspace.sh) with additional parameters (like --start_opencode) rather than creating parallel TUI-specific implementations, preserving backward compatibility and avoiding code duplication.

**workspace display name** — Unique user-facing name for a registered workspace, used in TUI menus and registry selection.

**container identity** — Stable workspace-specific identifier derived from the canonical workspace root, persisted with the workspace, and used to avoid container-name collisions.

**deferred build** — Registered workspace state in which the container image is not yet built; the workspace remains stopped until a later build and start.

**setup recovery** — Explicit retry path for incomplete first-run setup while preserving setup-complete as false until CBM and skills setup both succeed.

**credential bridge** — Activated `[credential] helper = store` block in the gitconfig template plus `configure_vcs_credentials` writing a host-scoped `https://<user>:<token>@<host>` entry into `.git_local/credentials` whenever a VCS token is captured — regardless of workspace source — so HTTPS clone and later push work with the same token in all editions. _Avoid_: credential-store side effect, token persistence.

**retry flow** — Error recovery pattern where users who choose "Retry" after a failure remain in the recovery loop even if intermediate steps (like settings adjustment) fail. Failures show context-aware error messages and return to the retry menu, except for explicit user aborts (exit code 2) which are respected throughout.

**uninstall wizard** — Guided TUI flow in Settings (warning screen with running containers and their stop commands, option rows for symlinks/config/backup toggled via Enter, explicit "Confirm — start uninstall" row that must be selected to proceed, summary screen). Every screen can be cancelled or navigated back; toggling a flag row alone never advances the wizard. The choices are mapped to uninstall.sh flags and run with `--force`.

**UNINSTALL confirmation** — Typed text confirmation required on the uninstall summary before anything is removed; rendered as a red gum input when gum is available, plain `read` fallback otherwise.

**web start option** — Launch style that runs the workspace container as a web server: the OpenCode v2 background service, pinned via the mounted service config (`service.json` hostname `0.0.0.0` / port 4096, pre-seeded on the host by start.sh before first start) with a single `opencode service start`, then a keep-alive (ADR 0024). Selectable at workspace creation and in settings; the server runs from the first start (first-run setup executes alongside via exec). Following the detached+exec start architecture, the detached container runs the service as its main process, the host port is auto-scanned upward from 4096 (like the CBM-UI range), and access announces a one-time pair link rather than opening a browser (the browser opens via the pinned Login WEB button only). The server is stopped via normal container stop. Direct CLI usage of start.sh with `--start_web` and without `--detach` runs `opencode serve` foreground, where Ctrl+C stops and removes the container (`--rm`). Implemented via the `--start_web` flag on start.sh, mirroring `--start_opencode`.

**pair link** — One-time web sign-in link printed by `opencode pair` (v2): opening it in a browser signs the session in (30-day session after that; links expire in 5 minutes). The TUI's web access runs `opencode pair --url http://<published-host>` inside the container so the link carries the reachable published authority, and announces it fresh at every web access — where the link also arms the pinned Login WEB button (opens the browser on click; the bottom toast stays the manual-copy backup). Not a stored credential; nothing about it is persisted. If pairing fails (or the access is part of first-run setup), web access falls back to announcing the plain web URL. _Avoid_: web URL (the plain published URL alone does not sign in), login URL.

**shared background service** — The OpenCode v2 client-server runtime model inside a workspace container: one background server owns sessions, config reload, permissions, and tool execution; every client (TUI, mini, run, web browser) connects to it. Auto-starts on first `opencode` use; the web start option pins and starts it explicitly. Never shipped disabled (`service set disabled true` is forbidden in the image) and `--standalone` (a private server per client) is never the standard. _Avoid_: standalone mode, per-client server.

**console session** — Interactive bash shell attached to a running container via `podman exec -it --user dev <container> bash`, chosen by the TUI at access time. Independent of the configured start option (launch behavior) and of any other session already inside the container.

**squid allowlist scope** — The squid egress proxy governs outbound traffic from inside the container only. Host-browser access to published container ports (web UI, CBM UI) never traverses squid, so allowlist entries are never needed for ingress.

**skipped files** — Files that could not be removed during uninstallation because of missing permissions; tracked during removal and reported at the end with a hint to clean them up manually (e.g. with sudo).

**desktop shortcut** — OS menu launcher for the TUI created by the install script by default (one of the convenience artifacts, opt-out via `--no_shortcut`); exactly one platform-appropriate artifact per OS: a `.desktop` file named `oc-sandbox.desktop` with `Terminal=true` under `$HOME/.local/share/applications/` (Linux), a `.lnk` named `OC Sandbox.lnk` in the current Windows user's Start Menu written from inside WSL (Windows), or a minimal `.app` bundle named `OC Sandbox.app` in `~/Applications` (macOS). Display name is `OC Sandbox` on all platforms. Independent of symlinks.

**shortcut flag** — The former opt-in `--shortcut` parameter on the install script, now accepted as a no-op: the desktop shortcut is created by default and only deselected via `--no_shortcut`; it overwrites an existing artifact silently on re-install.

**shortcut removal** — Uninstall path for desktop shortcuts, offered as a wizard checkbox mapped to an uninstall.sh flag; removes shortcut artifacts pointing into the installation folder.

**shortcut icon** — Icon material for the desktop shortcut, provided under `dist/icons/` in platform subfolders (`linux/`, `windows/`, `macos/`) and processed at shortcut creation time: Linux installs the bundled hicolor PNG set into `$HOME/.local/share/icons/hicolor/` and the `.desktop` file references it by bare theme name (`Icon=oc-sandbox`, no path); Windows copies `icons/windows/oc-sandbox.ico` to `%LOCALAPPDATA%\oc-sandbox\oc-sandbox.ico` and points the `.lnk`'s `IconLocation` there (the Start Menu shell cannot render icons from `\\wsl.localhost\...` UNC paths; UNC is only a fallback); macOS generates the `.icns` from `icons/macos/oc-sandbox.iconset` with `iconutil` at install time and embeds it in the `.app` bundle. Missing icons never fail the shortcut — it is created without one.

**hicolor icon install** — Linux shortcut step copying `icons/linux/share/icons/hicolor/` into `$HOME/.local/share/icons/hicolor/` so the desktop entry resolves `Icon=oc-sandbox` through the icon theme. Best-effort: failures fall back to an icon-less shortcut.

**icns generation** — macOS shortcut step converting the bundled `.iconset` to `AppIcon.icns` using `iconutil` (ships with macOS); on failure the `.app` is created without an icon.

**change workspace settings** — TUI flow (Settings → Change Workspace Settings → workspace list) re-running the full prefilled settings sequence (edition, modes, start option, VCS, AI provider, proxy toggle) for any registered workspace, including running containers and workspaces with incomplete first-run setup. Changes are persisted to sandbox_config.json immediately and take effect on next container start; no live-apply. _Avoid_: project settings (the pre-rename label), edit settings, live settings.

**revisit sequence** — The shared prefilled settings chain (edition → modes → start option → VCS → AI provider, plus proxy) used by both the change-workspace-settings flow and the failure-recovery retry path; one implementation, reachable from either entry point. _Avoid_: settings redo, reconfigure loop.

**proxy toggle** — Per-workspace yes/no setting recorded as `use_proxy` in sandbox_config.json, passed to start.sh as `--use_proxy` on next start. Governs container-level proxy use only; the per-pod proxy member's lifecycle (`oc-proxy-<container-id>` inside the workspace's pod, ADR 0029) and the allowlist remain start.sh concerns, never edited here. _Avoid_: allowlist editor, proxy settings.

**next-start apply** — Contract that any settings change (including edition switch) is only recorded and never reconfigures a running container; applying requires a later stop/start, where a missing edition image gets the existing Build now / Build later / Go back prompt at start time. If the stored edition differs from a running container's edition, the next Open Workspace start surfaces the edition-mismatch prompt (see edition mismatch) instead of silently reusing the old container. _Avoid_: live apply, hot reload.

**edition mismatch** — Divergence between the edition recorded in sandbox_config.json and the edition a workspace's running container actually runs (read from the container's image name `opencode-sandbox-<edition>` via `podman ps`; no labels, nothing stored in the registry). Surfaced only by the Open Workspace start buttons (Console / OpenCode / Web) as a three-way prompt: **Switch** (explicitly confirmed `podman stop` of the old container, then a normal start with rebuilt args — all current settings ride along — continuing into the requested access), **Use current** (access the old container unchanged), **Cancel**. The old container is never stopped until the new edition's image exists (missing image gets the start-time build prompt first); a switch whose start fails leaves the workspace stopped with the error in the busy pane. Container center Start is unaffected and keeps reuse-running; restart covers the same never-destroy rule generally (preflight before stopping). _Avoid_: live apply (the switch is an explicit, confirmed replacement, never a silent one).

**BubbleTea TUI** — The TUI: full-window, mouse-first, keyboard-available, single Go binary (`oc-sandbox`). Built on Charm libraries: BubbleTea (application/controller), Bubbles (components), Lip Gloss (styling). Sole TUI since the parity-gate flip (#98) and the bash TUI deletion (#99); gum remains in use by the helper scripts only. _Avoid_: GPU TUI.

**terminal minimum size** — The smallest terminal where the Go TUI renders at all: the too-small overlay guard trips below 80×24. At startup, when the terminal is a TTY and smaller than the layout target 80×41 (the Edit Workspace settings AI provider pane unfolds with a provider entry opened unscrolled), `oc-sandbox` asks it to grow via the xterm window-size escape (`CSI 8 ; height ; width t`) — emulators that ignore the request fall back to the overlay at 80×24; an already-large terminal is never shrunk. The overlay text names both the minimum (80×24) and the recommended size (115×41). Startup only, no repeat requests mid-session. _Avoid_: window requirement, hard resize, per-screen minimum.

**release-time build** — Cross-compilation of the Go TUI happens in create-release.sh before the orphan release branch is cut: `dist/bin/oc-sandbox_<goos>_<goarch>` (linux/darwin × amd64/arm64, CGO off), tag injected via `-X main.Version`. Go source lives at repo root outside `dist/` and never enters the release branch. `dist/bin/` is gitignored. _Avoid_: committing binaries, duplicating Go source into dist/.

**terminal handoff** — Full-screen terminal suspension where the TUI pauses, releases the grid to a child process (e.g. `podman exec` console via tea.ExecProcess), and re-renders the window on return. Core event for interactive sessions (console/OpenCode); used for long-running external commands that need raw terminal I/O.

**embedded log pane** — TUI layout region streaming live output of long-running container operations (build/start/stop/first-run) while the app stays interactive elsewhere, replacing the current bash "simple status messages" UX. Rendered below the owning view's card; the Container center Build Images tab and the New Workspace create chain (build/init/credentials steps) both feed it from the task manager's streamed lines.

**background task** — Long-running operation (build/start/stop/export) running in a Go goroutine with progress/status surfaced via footer/health indicators, allowing free navigation while it runs. Completes asynchronously with an inline notification at completion point; queued one-at-a-time per workspace.

**confirmation popup** — Shared centered modal (shell package) shown over the dimmed card to confirm a triggered action before it runs. Keyboard: ←/→/Tab switch buttons, Enter activates the focused button, esc/q cancels anytime. Pointer: click outside cancels; default focus is Cancel. One-line title + one context line per action; fires only when no op is queued/running. Applied to Create Workspace (content summary with Confirm/Back), Restore Config, Build (Container view button/card double-click), Uninstall (after the typed confirm, on button click, red Confirm), Update (update menu, plain Confirm, glossary "update menu"), and Remove workspace from list (Edit Workspace settings removal pane, red Confirm). Quit keeps the existing guarded-exit footer prompt; start-time Build-now prompt (Build now / Build later / Go back) stays separate. _Avoid_: yes/no dialog (Create Workspace uses Confirm/Back), exit prompt (reserved for guarded exit).

**start variant** — The access a single open-workspace start resolves to: one of console, OpenCode TUI, or Web. The configured start option preselects the variant (configure it in the Settings pane); an explicit card start button or a keyboard preselection can pick a differing variant for just that start (e.g. Web on a console-configured workspace launches the container with --start_web) without touching the saved settings. Double-click always starts with the configured start option; Enter starts with the visually preselected one. Web picked while a container runs without a published 4096 port adopts web: the running container is replaced with a verified --start_web relaunch (verified stop → start, one attempt per access chain) — a console container can never switch to web live. _Avoid_: access mode, session kind, per-start override.

**card start buttons** — The Open Workspace card's third content row (Console / OpenCode / Web) that chains start + access in one gesture: clicking a button on the selected card (or Enter, or double-click) starts a stopped container, waits for verified success, and lands in the chosen variant — no separate access prompt. On a running container the chosen variant is entered directly (Web announces a fresh pair link, never a browser). Buttons on unselected cards merely select the card. Left/right on the card grid cycles the preselection; the settings pane's Start option row still changes the configured start option. _Avoid_: access prompt (removed from the card flow), per-card start menu.

**card last-used row** — The workspace cards' second content row in both card grids (Open Workspace and the Workspace settings screen): the registry's last_used stamp rendered as a relative date — `Today 13:04` (same local day), `Yesterday`, `n d ago` (up to six days), else the absolute local date. A workspace never stamped (legacy registry) keeps rendering its path instead of a blank row. _Avoid_: path row (superseded on stamped workspaces), last open date.

**Login WEB button** — The highlighted (accent-filled `shell.ButtonLines`) button pinned above the Workspace Settings pane heading on the Open Workspace screen: armed when a web access produces a fresh pair link, it opens the pair link in the browser through the platform opener (`xdg-open` / macOS `open` / Windows `cmd start`) via the terminal handoff — click-only, no cursor/Enter navigation. The button is removed once the open succeeds (the one-time pair token is consumed) and expires when the container stops or is replaced (fresh `podman ps` scan misses it) or a mismatch-switch/web-readopt relaunch begins; a successful later web access re-arms it. A failed opener (headless machine, SSH) surfaces a warn toast ("copy the link from the toast below") and keeps the button; the bottom pair-link toast stays as the manual-copy backup. View state only — a TUI restart just re-arms on the next web access. _Avoid_: login button (ambiguous), web button (reserved for the card's Web start variant).

**minimal TUI launcher** — The binary's terminal face after the WebUI-first flip (end state of the WebUI-first effort): exactly two buttons — Open WebUI and Quit — plus a URL/status line showing the running WebUI's full tokenized URL. The embedded WebUI server starts at binary launch and stops on quit; all workspace management lives in the WebUI, and the update check with its badge/menu moves there too (version stays reachable via `--version` and WebUI Settings). A second concurrent launch detects the already-running WebUI and exits with a pointer to that session's window. _Avoid_: start screen (nothing is started — the server runs from launch), Start WebUI button (renamed Open WebUI).

**Open WebUI button** — One of the minimal TUI launcher's two buttons: (re)opens the WebUI tab in the browser. The tab auto-opens at binary launch; the button covers a closed tab, a failed auto-open (headless machine, SSH), or later re-entry — opening via the platform opener (`xdg-open` / macOS `open` / Windows `cmd /c start`) through the terminal handoff, with the URL left in the TUI for manual copy when the opener fails. _Avoid_: Start WebUI (the webserver is not started by the button), Login WEB button (the per-workspace pair-link button of the full TUI).

**per-launch token** — The unguessable token carried in the WebUI's URL path, generated fresh at every binary launch and validated per request; never persisted, it dies with the process, so tokenized URLs from a previous launch are dead. Always visible in the minimal TUI launcher's URL/status line for manual copy. _Avoid_: pair token (opencode's one-time pair-link token, unrelated), stored credential.

**quit containers prompt** — The minimal TUI launcher's quit question, "Stop running containers before quitting? [y/N]": scope is every running oc-sandbox container (name-convention discovery), default leaves them running (detached containers outlive the launcher; an agent may be mid-task), esc cancels, and "stopped" is the existing graceful stop-container flow. Runs after the guarded exit (background work → press quit again); when quitting, the WebUI server pushes a best-effort server-shutdown event so open browser tabs end on a "server stopped — relaunch oc-sandbox" screen instead of a dead connection. _Avoid_: exit prompt (the guarded-exit footer prompt), confirmation popup.

**remove workspace from list** — Deregistering a registered workspace from the Edit Workspace settings screen: deletes the workspace's entry from workspaces.json only (registry metadata). Untouched: global_config.json, the workspace's files, sandbox_config.json, and the workspace's container — a running container keeps running, simply no longer tracked. Gated two-step: the selected card's remove button opens a right pane with info text and warning, and only the pane's "Remove workspace from list" button behind the shared confirmation popup (red Confirm, default focus Cancel) performs the write. _Avoid_: delete workspace (reads like delete container or file deletion), unregister workspace, project list (the pre-rename label).

**muted card frame** — Frame treatment of unselected cards in the card grids: the rounded border renders in the unfocused border color instead of the accent (workspace cards via `shell.CardMuted`; the edition cards of the build view style their own muted border). Content is untouched; only the frame is muted. _Avoid_: dimmed card (reserved for modal popup overlay), disabled card (buttons of unselected cards still select).

**websearch** — OpenCode's built-in web-search tool, active in every sandboxed OpenCode instance whose search mode is websearch (see search_mode) via the `OPENCODE_ENABLE_EXA=1` and `OPENCODE_ENABLE_PARALLEL=1` container env vars set by start.sh, with `"websearch": {"provider": "random"}` seeded into the OpenCode config (random backend pick, auto-switch on rate limit). Needs no API key. Backend endpoints are Exa (`https://mcp.exa.ai/mcp`) and Parallel (`https://search.parallel.ai/mcp`); `OPENCODE_WEBSEARCH_PROVIDER=exa`/`parallel` env or config pin overrides the random pick. Under `--use_proxy` it requires the squid allowlist entries `mcp.exa.ai` and `search.parallel.ai`. _Avoid_: Exa search, web search tool.

**Context7** — Remote MCP server (`mcp.context7.com/mcp`) seeded into every sandbox's OpenCode config for documentation search; keyless (rate-limited free tier). Under `--use_proxy` it requires the squid allowlist entry `mcp.context7.com`. _Avoid_: docs MCP, exa MCP (websearch is a built-in tool, not an MCP server).

**oc-searxng** — The SearXNG image (`dist/searxng/Dockerfile`, outside the edition stage registry, so never offered as a workspace edition) run as a **per-workspace pod member** (ADR 0029): start.sh starts one detached `oc-searxng-<container-id>` container inside the workspace's pod (`opencode-sandbox-pod-<container-id>`, network mode `pasta:--ipv4-only`) when the workspace's search mode is searxng — image auto-built if missing, settings.yml bind mount, generated secret, no port publish. The workspace container reaches it over pod-internal loopback via the `SEARXNG_URL=http://127.0.0.1:8080 (bare base URL — mcp-searxng appends /search itself)` constant — no shared host-side instance, no service-port scan, no hosts-entry (under pasta, `host.containers.internal` resolves to the container's own address and can never reach loopback-published ports). The member is recreated with the pod on every start and goes down with it on stop/delete. Listed in the Container center Build Images tab as a non-edition row and in Delete Images as part of the sandbox family. Never runs under the squid proxy: SearXNG search is mutually exclusive with `use_proxy` (the SearXNG MCP reads arbitrary URLs, so the allowlist could not bound the agent — incompatible, not unproxied-by-exception, ADR 0026). _Avoid_: searxng image (the upstream image), shared searxng container (the retired host-side topology).

**SearXNG MCP** — The npm package `mcp-searxng` (ihor-sokoliuk, pre-installed globally in the base image together with the node runtime it needs, so every edition can serve the server — not just web, whose stage reuses the base node for its dev toolchain) registered as a local MCP server inside the workspace container: tools `searxng_web_search` (query → the pod's SearXNG member's JSON API) and `web_url_read` (fetches page content). Seeded into the workspace's opencode.json when the workspace's search mode is SearXNG, removed otherwise (applied at next container start). Its base URL is never written into opencode.json — start.sh carries it per container in the `SEARXNG_URL=http://127.0.0.1:8080 (bare base URL — mcp-searxng appends /search itself)` env constant (the per-pod instance's loopback address, ADR 0029), so nothing about the address can go stale. _Avoid_: websearch MCP (websearch is the built-in Exa/Parallel tool), fetch MCP (web_url_read is one tool of this server, not the server's identity).

**search_mode** — Per-workspace web-search setting (one choice row in the settings flows: none / websearch / SearXNG, positioned directly after the proxy toggle) recorded as `search_mode` in sandbox_config.json; absent reads as `websearch` for pre-existing workspaces. `none` seeds no search tooling at all (no Exa/Parallel env vars, no `"websearch"` config seeding, no MCP); `websearch` is today's built-in Exa/Parallel behavior including the `"websearch": {"provider": "random"}` seeding; `searxng` seeds the SearXNG MCP in opencode.json (no Exa/Parallel env vars, no seeding — SearXNG is the only web search; Context7 stays) and is started via start.sh `--search_mode searxng`. `searxng` is mutually exclusive with `use_proxy` (rejected combination); all modes apply on next container start, never live. _Avoid_: use_searxng toggle (superseded three-way design), websearch toggle.
